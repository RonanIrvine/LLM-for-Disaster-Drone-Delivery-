# LLMs for UAV Resource Distribution in Disasters

An LLM-powered AI agent that converts natural-language disaster scenarios into
formal Constraint Satisfaction Problems (CSPs), then uses the Z3 theorem prover
to formally verify that a generated drone delivery plan actually satisfies
every operational constraint — capacity, energy, timing, and delivery
requirements — before it's trusted.

This is the codebase for my Master's thesis at Auckland University of
Technology: *"LLMs for UAV Resource Distribution in Disasters: Enhancing
Trustworthiness through Formal Verification"* 

## How it works

1. **Natural-language input** — a disaster manager describes the scenario
   in plain English (nodes, distances, resources, drones).
2. **LLM parsing** (GPT) — extracts structured parameters into a JSON object,
   validated against Pydantic models (`Edge`, `Drone`, `ProblemParams`).
3. **Code generation** (GPT) — writes a bespoke `run_z3_solver(params)`
   function tailored to the scenario's constraints. Syntax/bracket errors
   trigger an automatic repair loop (up to 5 retries).
4. **Z3 solving** — checks satisfiability and, if solvable, extracts optimal
   drone routes (minimizing energy, then trip count).
5. **Logging** — every stage's output (user input, JSON params, generated
   solver code, final plan) is saved as a timestamped artifact for auditing.

```

  input.json               Sample disaster scenario (4 nodes, 2 drones)
```

## Setup

```bash
python -m venv venv
source venv/bin/activate   # venv\Scripts\activate on Windows
pip install -r requirements.txt
export OPENAI_API_KEY=your-key-here   # or a .env file (never commit it)
python drone_planner.py
```

## Notes

- `artifacts/` is created at runtime to log each session (user input, JSON,
  generated code, and solver output). It's git-ignored on purpose — it fills
  up with session-specific data and could contain leftover API responses.
- `generated_solver.py` in `examples/` is a **sample artifact**, not source
  code you're meant to edit directly — the whole point of the pipeline is
  that this file gets regenerated per scenario.

## Status / Limitations

See section 7.4 of the thesis for a full discussion. Briefly: the system is
more reliable when the input constraints are expressed in natural language
than in pseudocode, bounded variable domains limit scalability to larger
graphs, and there's a known issue with how the source node is treated in the
delivery-time-separation constraint.
